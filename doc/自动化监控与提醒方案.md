## 2. 需要创建的自动化任务

### 2.1 每日数据巡检（Daily Data Check）

**配置：**
| 字段 | 值 |
|------|-----|
| 名称 | ClassroomTimers 每日数据巡检 |
| 频率 | 每天 09:00（北京时间） |
| 类型 | recurring |
| rrule | `FREQ=DAILY` |
| 工作目录 | `/Users/miracle/Documents/code/moyan/classroom-timers` |

**执行内容：**

1. 调用 Plausible Stats API 拉取以下数据：
   - 昨日 PV / UV / 平均会话时长
   - 昨日 Top 10 页面（按 PV）
   - 昨日流量来源 TOP 5
   - 昨日国家/地区分布 TOP 5
   - 昨日设备分布（桌面/手机/平板）

2. 与 7 日移动平均对比，计算变化率

3. 写入日刊日志到 `.workbuddy/memory/analytics-logs/YYYY-MM-DD.md`

4. 触发判断：
   | 条件 | 动作 |
   |------|------|
   | PV 较 7 日均值下降 > 30% | ⚠️ 标记异常，提醒检查 |
   | PV 较 7 日均值上升 > 50% | ✅ 标记增长，建议分析来源 |
   | 新上线工具页 7 天仍无流量 | ⚠️ 提醒检查收录状态 |
   | 某国家流量占比 > 15%（非 en 国家） | 💡 建议评估该语言支持 |
   | 某来源渠道突然出现 | 💡 提醒关注该渠道 |

### 2.2 每周任务提醒（Weekly Task Reminder）

**配置：**
| 字段 | 值 |
|------|-----|
| 名称 | ClassroomTimers 每周任务提醒 |
| 频率 | 每周日 20:00（北京时间） |
| 类型 | recurring |
| rrule | `FREQ=WEEKLY;BYDAY=SU` |
| 工作目录 | `/Users/miracle/Documents/code/moyan/classroom-timers` |

**执行内容：**

1. 读取 `doc/迭代计划-2个月.md`，找到当前周（按日期匹配）的任务

2. 汇总过去一周的数据：
   - 本周总 PV / UV
   - 周环比变化
   - Top 新增页面表现
   - 异常事件回顾

3. 输出提醒消息：
   ```
   📋 本周任务（Aug 10–16）：
   □ Day 1：Interval Timer（/timer/interval-timer）
   □ Day 2：时长页面扩展（+4 个页面）

   📊 上周数据摘要：
   - 总 PV：xxx，环比 +x%
   - Top 页面：xxx
   - 新收录页面：x 个

   ⚠️ 需要关注：xxx
   ```

4. 判断计划是否需要调整：
   | 条件 | 建议 |
   |------|------|
   | 某工具页流量远超预期 | 提前加码该工具的推广/内容 |
   | 长时间无自然搜索流量 | 优先 SEO 审计而非新功能 |
   | 某国家流量意外爆发 | 考虑提前支持该语言 |
   | 周任务连续 2 周未完成 | 建议降负载、砍低优任务 |

## 4. Plausible API 接口清单

基础 URL：`https://analytics.bufferbloattest.org/api/v1`

| 接口 | 用途 | 参数 |
|------|------|------|
| `GET /stats/timeseries` | 时序 PV/UV | `site_id`, `period=custom`, `date=YYYY-MM-DD,YYYY-MM-DD`, `interval=date` |
| `GET /stats/breakdown` | 分维度排行 | `site_id`, `period=day`, `date=YYYY-MM-DD`, `property=event:page\|visit:source\|visit:country\|visit:device`, `limit=10` |
| `GET /stats/aggregate` | 汇总指标 | `site_id`, `period=day`, `date=YYYY-MM-DD` |
| `GET /stats/realtime/visitors` | 实时访客 | `site_id` |

认证方式：`Authorization: Bearer <API_KEY>`

Python 调用示例：
```python
import requests
import json

BASE = "https://analytics.bufferbloattest.org/api/v1"
HEADERS = {"Authorization": f"Bearer {API_KEY}"}

# 昨日汇总
resp = requests.get(
    f"{BASE}/stats/aggregate",
    params={"site_id": "classroomtimers.app", "period": "day", "date": "2026-08-05"},
    headers=HEADERS
)
data = resp.json()
```

## 6. 判断逻辑：何时调整计划

| 信号 | 阈值 | 建议动作 |
|------|------|---------|
| 连续 3 天 PV 下降 | > 30% vs 7日均值 | 检查是否有技术问题（部署失败、JS 报错等） |
| 新页面 7 天未收录 | GSC status = 未收录 | IndexNow 重新推送 + GSC 手动提交 |
| 某页面点击量高但排名低 | CTR > 5%，排名 > 10 | 优化该页 meta description 和 H1 |
| 某来源突然贡献大量流量 | 新来源 > 20% | 分析该来源特性，加码运营 |
| 某国家流量占比持续 > 15% | 非当前语言国家 | 提前规划该语言支持 |
| 移动端流量占比 > 60% | 持续 7 天 | 优先移动端体验优化 |
| 任务连续 2 周末完成 | — | 从计划中砍掉低优任务 |
| PV 持续增长且无异常 | 周环比 > 20% | 按原计划推进，不加塞 |

## 8. 成本与风险

| 项目 | 说明 |
|------|------|
| Plausible API | 自托管实例，无调用次数限制，无费用 |
| 自动化运行 | WorkBuddy 内置能力，无需额外工具 |
| 数据存储 | 本地 markdown 文件，每份日志约 1-2 KB |
| 误判风险 | 初期可能有误判（如正常波动被标为异常），随数据积累会逐步校准 |
| 失联风险 | 自动化依赖于 WorkBuddy 处于运行状态，如果电脑关机则错过当次执行 |
