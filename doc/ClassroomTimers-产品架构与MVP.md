# ClassroomTimers 产品架构与 MVP

版本：v1.4  
域名：classroomtimers.app  
定位：面向教师、培训师与学习者的课堂时间与节奏工具

## 1. 最终价值

ClassroomTimers 不应只是一个“在线倒计时网站”，而应成为教师控制课堂节奏时最快、最清楚、最可靠的屏幕工具。

用户真正购买或反复使用的不是“计时能力”，而是以下结果：

- 教师可以在 10 秒内开始一个全班都看得清的计时任务。
- 学生不需要反复询问还剩多久，课堂预期更稳定。
- 转场、讨论、测验、阅读、休息等环节更容易按计划完成。
- 常用课堂流程可以复用、收藏、投屏和分享，不必每次重新设置。
- 工具在电脑、平板、手机、投影仪和旧设备上都有一致体验。

一句话价值主张：

> Make every minute visible.

长期产品定义：

> ClassroomTimers 是一套以“可视时间”为核心的课堂节奏工具箱：打开即用，远距离可读，按场景复用，并能逐步沉淀为教师自己的课堂模板库。

## 2. 核心用户与任务

### 2.1 首要用户：教师与培训师

核心任务：

- 给课堂活动设置明确时限。
- 在投影或大屏上让所有学生看到剩余时间。
- 快速暂停、延长、缩短或重新开始。
- 为常见活动复用相同设置。
- 在计时结束时用声音或视觉提示收束活动。

典型场景：

- 课堂热身、独立练习、小组讨论、阅读、写作、展示、转场、课间休息。
- 随堂测验、正式考试、口语展示、实验观察、体育训练。
- 教师培训、企业内训、工作坊与会议控时。

### 2.2 次要用户：学生与家庭学习者

核心任务：

- 自习、番茄专注、模拟考试和作业时间管理。
- 使用静音视觉提醒，减少频繁查看手机。
- 在平板或副屏上长期显示时间。

### 2.3 后续扩展用户

- 会议主持人与演讲者。
- 健身、冥想和间歇训练用户。
- 需要大字时钟的家庭与公共空间。
- 需要跨时区协作的远程团队。

产品扩展可以覆盖这些人群，但第一阶段的品牌、首页和模板应始终优先服务课堂。

## 3. 完整产品架构

### 3.1 产品能力分层

#### A. 即开即用层

这是所有流量的第一落点，不要求登录。

- Classroom Timer：课堂倒计时，支持数字与可视进度。
- Egg Timer：用沙漏/鸡蛋计时器的视觉隐喻表达剩余时间。
- Candle Timer：用蜡烛燃烧高度表达剩余时间，适合安静阅读与低刺激课堂。
- Stopwatch：正向计时与分段记录。
- Visual Timer：用颜色面积直观表达剩余时间。
- Interval Timer：轮次、工作/休息与重复次数。
- Digital Clock：大屏数字时钟，支持主题风格、背景与显示设置。
- Flip Clock：具有翻页视觉效果的大屏时钟，支持风格与背景切换。
- World Clock：跨时区课程与协作。
- Alarm：指定时间提醒。

所有工具共享：

- 全屏显示。
- 屏幕常亮。
- 标签与主题。
- 工具设置入口，以及适用于该工具的风格、背景与显示选项。
- 声音、静音闪烁和音量设置。
- 键盘快捷键。
- URL 参数与分享链接。
- 响应式布局。
- 本地保存与最近使用。

#### B. 课堂场景层

将通用计时能力包装成教师能直接理解的入口。

- 课堂活动：热身、阅读、写作、讨论、展示、收拾与转场。
- 测验考试：5/10/20/45/60/90 分钟。
- 专注学习：25/5、50/10 与自定义番茄节奏。
- 小组协作：多轮讨论、站点轮换、辩论与答题。
- 感官友好：无声音、低刺激、高对比和儿童友好的可视主题。
- 演讲培训：发言倒计时、黄灯提醒、红灯结束。

每个场景页面都应同时包含：

- 可立即运行的工具。
- 推荐预设。
- 简短使用说明。
- 可复制分享的配置链接。
- 相关场景与工具内链。

#### C. 课堂互动层

在计时之外，解决同一堂课中的高频组织任务。

- Random Name Picker：随机点名。
- Group Generator：随机分组。
- Classroom Scoreboard：课堂计分板。
- Noise Meter：噪音提示。
- Classroom Screen：时间、任务、二维码、文本提示的组合大屏。

这一层是长期差异化的重要来源，但不应阻塞第一版计时核心上线。

#### D. 复用与分享层

- 最近使用。
- 收藏预设。
- 自定义名称、颜色、声音和结束动作。
- URL 参数分享。
- 短链接与二维码。
- 模板复制。
- 一键添加到主屏幕。
- 教师公开模板页。

#### E. 教师工作区

登录后提供：

- 我的计时器。
- 我的课堂模板。
- 模板文件夹与排序。
- 多设备同步。
- 课堂品牌设置。
- 团队或学校共享模板。
- 使用历史与常用场景。

#### F. 内容与增长层

- 工具页：承接明确的功能搜索意图。
- 场景页：承接 classroom、exam、speech、study 等意图。
- 时长页：5 minute timer、10 minute timer 等程序化页面。
- 教师资源：课堂活动设计、时间管理方法、可下载模板。
- 指南与 FAQ：全屏、常亮、声音、投屏和隐私说明。

#### G. 商业化层

免费版：

- 无需登录使用核心工具。
- 本地保存有限预设。
- 基础主题与声音。

Premium：

- 去广告。
- 无限预设与云同步。
- 高级主题、声音与组合课堂屏幕。
- 品牌化分享页。
- 团队模板与学校空间。

广告应只出现在内容区和非执行状态，绝不能遮挡计时舞台、控制按钮或全屏模式。

路由原则：

- 首页是 Classroom Timer 的唯一标准倒计时入口，打开后直接操作，不先经过营销页。
- `/digital-clock` 承接 Digital Clock 搜索意图，提供大屏数字时钟、主题风格、背景与显示设置。
- `/egg-timer` 与 `/candle-timer` 使用独立顶级路径承接明确工具意图，但不进入顶部一级菜单。
- 一个 URL 只服务一个主要搜索意图，并保持一个清晰 H1。
- 工具状态通过短参数表达，例如 `?m=10&label=Group%20Work&sound=bell`。
- 页面正文使用服务端渲染，计时交互在客户端运行。
- 国际化使用语言目录，例如 `/zh/`、`/es/`；英语保留在根路径，不拆分域名。

### 3.3 导航架构

顶部一级菜单固定为以下五项：

- Home：`/`。
- World Clock：`/world-clock`。
- Flip Clock：`/flip-clock`。
- Digital Clock：`/digital-clock`。
- Stopwatch：`/stopwatch`。

约束：

- 不在顶部增加 Egg Timer、Candle Timer、Visual Timer、时长页或模板页。
- 不使用展开后覆盖大量页面的 Mega Menu。
- 如果某个一级工具存在二级能力，将入口放在该一级页面内部的“Styles / Related timers / Popular durations”区块。
- SEO 长尾链接与真实用户任务一起组织，不在顶部导航或页脚堆成关键词列表。
- 每个页面默认展示 4–8 个最相关入口；更多内容使用“View all”进入聚合页。
- 入口区采用留白充分的文字链接、紧凑按钮或小卡片，不占满整个视口，不与主工具争夺首屏注意力。
- 语言选择器是辅助操作，不计入一级工具菜单；桌面放在导航右侧，移动端放入简洁菜单或设置面板。

### 3.4 页面结构

#### 首页

1. 品牌导航与工具切换。
2. 第一屏直接提供 Classroom Timer、快捷时长、课堂预设与 Settings。
3. 第二屏使用克制的 Classroom Tools 区块展示已上线的相关工具；Random Name Picker、Group Generator 等后续工具上线后也统一进入此区块。
4. 核心优势：全屏、常亮、分享、隐私。
5. 典型课堂场景。
6. 使用说明与 FAQ。
7. 页脚与法律链接。

#### 工具页

1. 唯一 H1，可视觉隐藏但必须语义明确。
2. 工具舞台。
3. 最近使用或推荐预设。
4. 使用说明。
5. 典型场景。
6. FAQ。
7. 相关工具与模板。

一级工具页的二级入口区：

1. 使用一个清晰 H2 解释这组入口的用户价值。
2. 优先显示与当前工具强相关的 4–8 个链接。
3. 首页第二屏链接到 Egg Timer、Candle Timer、Visual Timer、常用时长页和已上线的课堂互动工具。
4. Digital Clock 与 Flip Clock 页面内部展示各自的风格与背景预设，不为每个视觉风格创建顶部菜单项。
5. World Clock 页内部提供时区概念、重点国家与城市入口。
6. 链接区最多占一个普通内容章节，不做全屏链接墙或标签云。

#### 场景页

1. 场景名称与结果导向文案。
2. 已配置好的工具。
3. 2–6 个场景预设。
4. 教师使用建议。
5. 相关时长页与工具页。

### 3.5 状态与数据模型

统一的 Timer Config 应作为工具、模板和分享链接的共同协议：

```ts
type TimerConfig = {
  mode: 'countdown' | 'stopwatch' | 'visual' | 'interval'
  durationSeconds?: number
  label?: string
  theme?: string
  sound?: string
  volume?: number
  style?: string
  background?: string
  warningAtSeconds?: number
  showProgress?: boolean
  autoFullscreen?: boolean
  wakeLock?: boolean
}
```

状态优先级：

1. URL 参数：用户打开别人分享的配置。
2. 当前会话状态：运行、暂停、结束。
3. 本地预设与最近使用。
4. 登录后的云端预设。
5. 产品默认值。

本地优先原则：

- 不登录也能完成完整计时流程。
- 第一版预设、最近使用和偏好保存在 `localStorage`。
- 计时基于绝对时间戳，而不是依赖动画帧累加。
- 云端只在账户功能上线后承担同步，不成为工具可用性的单点依赖。
- 可分享的工具设置写入 URL；音量、Wake Lock 等设备偏好只保存在本地，不默认写入分享链接。

### 3.6 设置系统

所有需要配置的工具使用统一的 Settings 入口与面板骨架。

通用设置：

- 风格与背景。
- 声音、音量和静音视觉提醒。
- 屏幕常亮。
- 全屏。
- 显示精度、12/24 小时制等工具相关显示项。
- 重置为默认设置。

工具专属设置：

- 首页 Classroom Timer：计时类型（单次 / 循环）、循环时的工作/休息时长与轮次、报警声开关与音色选择（至少 3 种）、进度样式、警示时间、结束动作。
- Egg Timer：沙粒/填充动画风格、容器颜色、背景。
- Candle Timer：蜡烛样式、火焰动效、背景和低动态模式。
- Digital Clock：数字主题、字体观感、秒数、日期、12/24 小时制和背景。
- Flip Clock：字卡风格、字体观感、秒数、12/24 小时制、背景。
- World Clock：时间格式、城市排序、昼夜层、时差显示和工作时段。
- Stopwatch：小数精度、分段显示和声音反馈。

MVP 的 Digital Clock 与 Flip Clock 均至少提供 4 种风格与 6 个预设背景。MVP 不支持用户上传背景，但设置结构必须允许后续扩展。

资产交付规则：

- 音效和背景随站点部署到本地静态目录，不在运行时热链第三方 CDN。
- MVP 音效从允许商业项目使用的素材库中筛选并下载，保留原始页面、许可、作者与下载日期记录。
- MVP 背景优先使用 CSS 色彩、轻纹理和原创生成素材；需要照片时才从许可清楚的图库下载。
- 所有音频与图片在入库前完成裁剪、响度检查、压缩、尺寸优化和可读性检查。

### 3.7 世界时钟与时区教育

世界时钟不能只展示“城市现在几点”，还要让第一次使用的用户理解：

- 时区以 UTC 偏移为共同基准。
- GMT 与 UTC 在日常表达中的关系。
- 夏令时会让部分城市的 UTC 偏移随日期变化。
- 一个国家可能有多个时区，不能用国家直接替代城市时区。
- 跨过国际日期变更线后会出现昨天、今天或明天。

工具界面应同时提供：

- 城市本地时间。
- IANA 时区名称。
- 当前 UTC 偏移。
- 相对用户本地时差。
- 昨天/今天/明天。
- 夏令时状态。
- 昼夜与可选工作时段提示。

说明内容放在工具下方并服务端渲染；地图和卡片负责直观理解，正文负责解释概念。

### 3.8 技术架构

技术结构：

- 展示层：Next.js App Router + TypeScript + Tailwind。
- 交互层：按工具拆分的 Client Components。
- 页面层：服务端渲染的元数据、正文、FAQ 和内链。
- 本地数据层：URLSearchParams + localStorage。
- PWA 层：Manifest、Service Worker、离线壳与主屏安装。
- 后端层（后续）：认证、模板同步、团队、支付和短链接。
- 分析层：只记录匿名产品事件，不记录标签文本或课堂内容。

源码目录：

```text
src/
├── app/
│   ├── (public)/                 # 首页与公开工具路由
│   ├── layout.tsx                # 根布局与全站 Provider
│   └── globals.css               # 全局 Token 与基础样式
├── components/
│   ├── layout/                   # Header、Footer 等全站布局
│   ├── marketing/                # 服务端可读的内容与 SEO 组件
│   └── ui/                       # 无业务语义的基础 UI
├── config/                       # 导航、站点与功能开关配置
├── features/
│   ├── timer-core/               # 计时、全屏、常亮等共享领域能力
│   ├── classroom-timer/          # 首页 Classroom Timer
│   ├── stopwatch/
│   ├── flip-clock/
│   └── world-clock/
└── lib/                          # 跨领域且与业务无关的基础函数
```

目录约束：

- `src/app` 只负责路由、Metadata、服务端内容和功能组合，不承载可复用业务实现。
- 每个产品能力放入独立的 `src/features/<feature>`，并在功能内部按需使用 `components`、`hooks`、`data`、`lib`、`types` 和 `server` 子目录。
- `timer-core` 只承载多个时间工具共同使用的领域能力，不接收单一工具的页面文案或专属视觉。
- `src/components` 只存放跨功能复用组件；只被一个工具使用的组件保留在对应 Feature 内。
- 全站静态配置放在 `src/config`，无业务语义的纯函数放在 `src/lib`。
- 认证、数据库、支付和权限上线时放入 `src/server`；对应页面分别使用 `src/app/(auth)` 与 `src/app/(dashboard)` 路由组。
- Route Handler 放入 `src/app/api`，不得从客户端组件直接导入 `src/server`。
- 单元测试与功能文件相邻放置，端到端测试上线后统一放入根目录 `tests/e2e`。
- 根目录只保留框架配置、依赖清单、`public`、`doc` 和项目级工具配置。

核心质量要求：

- 计时准确，不因标签页降频而漂移。
- 断网后已加载工具仍可使用。
- 全屏时不出现导航、广告或无关正文。
- 页面打开后主工具优先可交互。
- 计时结束提示在不支持声音或通知时有视觉回退。
- 键盘、触控和鼠标均可完成核心流程。

## 4. 第一版 MVP

### 4.1 MVP 目标

验证一个核心假设：

> 教师是否愿意把 ClassroomTimers 作为课堂投屏计时的固定入口，并在一周内重复使用或分享预设链接。

MVP 不以工具数量为成功标准，而以“第一次使用足够快、课堂中足够稳、下一次愿意再来”为标准。

### 4.2 必须上线的内容

| 模块 | MVP 必须具备 | 验收标准 |
| --- | --- | --- |
| 品牌 | ClassroomTimers 名称、Logo、域名和统一文案 | 全站统一使用 ClassroomTimers 品牌 |
| 首页主工具 | 课堂倒计时 | 打开首页即可设置并开始，不需要跳转或登录 |
| 时间设置 | 滚轮、自定义输入、1/3/5/10/15/20/30/45/60 分钟快捷项 | 两次操作内启动常用时长 |
| 执行控制 | 开始、暂停、继续、重置、增加/减少 1 分钟 | 运行中误操作可恢复，按钮状态清楚 |
| 可视反馈 | 大数字、进度环、最后 10 秒警示、结束状态 | 教室后排可读，不能只依赖颜色表达状态 |
| 提醒 | 至少 3 种声音、静音闪烁、音量预览 | 浏览器无法播放声音时仍有视觉提示 |
| 课堂标签 | 可编辑活动名称 | 标签同时显示在大屏与分享链接中 |
| 全屏与常亮 | Fullscreen + Screen Wake Lock | 不支持时隐藏或提供清楚回退说明 |
| 分享 | URL 参数、复制链接、二维码 | 新设备打开后还原同一配置 |
| 复用 | 最近使用、本地收藏预设 | 刷新或重新打开后可再次启动 |
| 工具设置 | 统一设置按钮、面板结构和本地持久化 | 每个有可配置项的工具都能从同一位置进入设置 |
| 秒表 | 开始、暂停、继续、复位、分段 | 功能、品牌与交互体验保持全站一致 |
| 倒计时风格 | Egg Timer、Candle Timer 独立页面 | 与首页 Classroom Timer 共用可靠计时内核，具有清楚的专属视觉表达 |
| 数字时钟 | 至少 4 种主题风格、6 个预设背景与显示设置 | 承接 Digital Clock 意图，设置刷新后保留且所有组合远距离可读 |
| 翻页时钟 | 至少 4 种风格、6 个预设背景与显示设置 | 设置在刷新后保留，所有组合保持远距离可读 |
| 世界时钟 | 时区概念、重点国家与城市、UTC/时差/DST/日期偏移 | 不把多时区国家简化为单一国家时间 |
| 多语言 | 英语与简体中文的工具 UI、元数据、核心正文和错误状态 | 不允许只有菜单翻译、正文仍混用其他语言 |
| 响应式 | 手机、平板横竖屏、桌面与投影 | 320 px 至大屏均无横向溢出和关键遮挡 |
| 内容 | 首页说明、核心工具页正文、FAQ、隐私与条款 | 可被抓取，正文不依赖客户端渲染 |
| SEO 基础 | Metadata、canonical、sitemap、robots、结构化 FAQ | 每页一个主要意图与一个 H1 |
| 可访问性 | 键盘操作、焦点样式、ARIA、对比度、减少动态效果 | 核心流程达到 WCAG 2.2 AA 基线 |

### 4.4 MVP 首发多语言

MVP 使用英语作为根路径默认语言，并提供简体中文与繁体中文：

| Locale | 主要覆盖市场 | 选择原因 |
| --- | --- | --- |
| `en` | 美国、英国、加拿大、澳大利亚、印度及全球英语教育市场 | 默认语言与最大范围入口 |
| `zh` | 中国大陆及简体中文用户 | 服务中文用户与现有产品内容迁移 |
| `zh-hant` | 台湾、香港、澳门及繁体中文用户 | 覆盖繁体中文课堂与自学场景 |

Locale 路由：

- 英语使用根路径，例如 `/digital-clock`。
- 简体中文使用 `/zh` 目录，例如 `/zh/digital-clock`。
- 繁体中文使用 `/zh-hant` 目录，例如 `/zh-hant/digital-clock`。
- 所有可索引页面输出对应 canonical、完整 hreflang（`en` / `zh-CN` / `zh-Hant`）与 `x-default`。
- URL slug 首版保持英文，避免同一工具出现多套难维护路径。
- 工具 UI、设置、错误、元数据、结构化数据、正文与 FAQ 必须同步翻译。
- 时间、数字、日期、12/24 小时制和城市名称使用 Locale 规则格式化，不拼接硬编码英文。

其他语言根据首发流量、用户反馈与搜索数据安排后续优先级。

实现依据：

- Google Search Central 的 [多语言页面管理](https://developers.google.com/search/docs/advanced/crawling/localized-versions) 与 [x-default 指南](https://developers.google.com/search/blog/2023/05/x-default)。
- Unicode CLDR 的 [日期、时间、时区与城市名称规范](https://cldr.unicode.org/translation/date-time)。

### 4.5 世界时钟 MVP 覆盖

默认城市池包含 13 个具有代表性的城市：

- Los Angeles、New York、São Paulo。
- London、Paris、Berlin。
- Johannesburg、Dubai、New Delhi。
- Singapore、Beijing、Tokyo、Sydney。

默认卡片不应全部同时铺满页面，可按用户本地时区与屏幕空间选择 6–8 个，其他城市通过管理面板添加。

首发可搜索范围至少覆盖以下 32 个重要国家：

- 北美：美国、加拿大、墨西哥。
- 南美：巴西、阿根廷。
- 欧洲：英国、法国、德国、西班牙、意大利、荷兰、瑞士、俄罗斯、土耳其。
- 中东与非洲：阿联酋、沙特阿拉伯、埃及、南非、尼日利亚。
- 南亚：印度、巴基斯坦、孟加拉国。
- 东亚与东南亚：中国、日本、韩国、新加坡、印度尼西亚、泰国、越南、菲律宾。
- 大洋洲：澳大利亚、新西兰。

美国、加拿大、墨西哥、巴西、俄罗斯、印度尼西亚和澳大利亚必须提供多个代表城市，明确同一国家存在多个时区。底层使用 IANA 时区标识，不存储固定 UTC 偏移。

时区规则会随政治决定持续变化，运行时与测试数据应跟随 [IANA Time Zone Database](https://www.iana.org/time-zones)，不能把当前 UTC 偏移当作永久常量。

### 4.6 MVP 暂不包含

- 登录、云同步和多设备同步。
- Premium 订阅与广告。
- 团队或学校空间。
- 模板市场与公开教师主页。
- Random Name Picker、Group Generator、Scoreboard。
- Alarm、Chess Clock、Metronome 和 Meeting Scheduler。
- 完全自由的主题编辑器、上传自定义音频或背景。
- 原生 App。
- 大规模程序化 SEO 页面。

这些能力均可进入后续架构，但不应增加首版路径、数据库或运营负担。

### 4.7 MVP 实施顺序

#### 阶段 1：品牌与核心路径

- 全站使用 ClassroomTimers 名称、Logo、图标、域名和品牌文案。
- 首页从通用时间工具集明确聚焦课堂计时。
- 接入正式 Logo、图标、域名和品牌文案。
- 所有产品代码遵循 `src/app`、`src/features`、`src/components`、`src/config` 与 `src/lib` 的职责边界。

#### 阶段 2：课堂计时闭环

- 补齐标签编辑、快捷时长、运行中加减时间、结束提醒。
- 补齐复制链接、二维码、最近使用与本地收藏。
- 补齐统一设置入口、Egg Timer、Candle Timer、Digital Clock 和 Flip Clock 预设风格/背景。
- 检查全屏、常亮、后台计时和声音回退。

#### 阶段 3：内容与发布基础

- 上线 Digital Clock、Egg Timer、Candle Timer、时长页、隐私和条款。
- 完成英语、简体中文与世界时钟重点国家数据。
- 完成 canonical、sitemap、robots 和结构化数据。
- 完成移动、平板横屏、桌面与投影的视觉检查。

#### 阶段 4：上线验证

- 记录匿名的开始计时、完成计时、使用预设、进入全屏、复制链接和 7 日回访事件。
- 根据真实复用数据决定优先做 Visual Timer、课堂互动工具还是账户同步。

## 5. MVP 成功指标

北极星指标：

- 每周完成的有效课堂计时会话数。

激活指标：

- 首次访问后 60 秒内成功开始一次计时。

留存指标：

- 7 天内再次开始计时的匿名设备比例。

价值指标：

- 使用预设或最近使用启动的会话比例。
- 进入全屏的会话比例。
- 分享链接被复制并在新设备打开的次数。

质量指标：

- 计时异常结束率。
- 声音播放失败率。
- Wake Lock 申请失败率。
- 核心 Web Vitals 与 JavaScript 错误率。

不使用页面浏览量作为唯一成功判断。ClassroomTimers 的真实价值来自重复课堂使用，而不是一次性搜索点击。
